# Cluster product briefs

Each brief is the MINIMUM scope for a real, working v1 of each module. Designers flesh
these out (columns, state machines, RPCs, pages) and may add depth that a Fleetio /
Samsara / Odoo / Zoho user would expect — but must stay buildable and testable.
Everything is multi-tenant, en+ar, RTL, light+dark, ME-first (GCC labor law, VAT via
`shared/countries.ts`, 3-decimal dinars).

Shared expectations for every module:
- A hub page at its route with tabs (use the `SalesHub` shape: PageHeader + pill tab nav + nested lazy routes), an Overview tab with KPI `StatCard`s and one or two charts where meaningful, list pages (`DataTable` + `listPage` + `Pagination`, server-side search/filters), detail pages for first-class entities (canonical URL), create/edit via `Modal`, role-gated actions (`isManager`/`isAdmin`), empty/loading/error states.
- Documents with a lifecycle get numbering, a DB-enforced state machine trigger, server-side stamps, and delete guards once past draft (docs/SALES.md posture).
- Deterministic analytics only (no fabricated "AI" text). Pure calculations live in `src/lib/<module>.ts` or `shared/<module>.ts` with vitest unit tests.

## Cluster `platform` → migration 20260924000002_platform_modules.sql
Modules: documents, notifications, workflow_automation, integrations, audit_security, multi_company.
(Foundation already created: documents table + bucket, notifications + preferences + state + refresh, api_keys, domain_events, companies, branches, module helpers.)

- **documents** — Document library (all tenant files: search, filter by category/entity/expiry, upload with drag-drop, preview images/PDF via signed URL, download, delete), expiring-documents view, and a reusable `<AttachmentsPanel entityType entityId />` component (in `src/pages/documents/AttachmentsPanel.tsx`) that other modules embed. Storage via supabase-js storage API (`supabase.storage.from('documents')`, signed URLs). Scanner `app.scan_due_documents` → `documents.expiring` notifications (30/7/0 days).
- **notifications** — Header bell (unread count, dropdown of latest, mark read/all read, link-through), `/notifications` inbox (filter unread/kind/severity), preferences tab (mute per kind). Localized rendering from `kind` + `params`. Must own the catalog of ALL notification kinds across clusters (the integration step feeds it the final list). Ships `app.scan_due_core(p_tenant)` for pre-existing tables: renewals due (30/7/0/overdue), driver license expiry, service reminders due (by date and by odometer), SL certificates expiring (30/7/0), invoices overdue. Plus event triggers on existing tables (gated + exception-safe, per FOUNDATION §0.2): issue created with high/critical priority → managers; work order completed; inspection failed.
- **workflow_automation** — Rules: `automation_rules` (name, event (from a catalog of domain events), conditions jsonb (list of {field, op: eq|neq|gt|gte|lt|lte|contains|in, value} evaluated against the event payload), actions jsonb (list of: notify {audience|user, severity, message}, create_issue {vehicle from payload, title, priority}, webhook {subscription id}, set_field? (NO — keep safe), assign_field_task? (NO — cross-cluster)), active, run_count, last_run_at), `automation_runs` (rule, event id, status success|skipped|failed, detail). REPLACES `app.emit_event` to also evaluate active rules synchronously (definer, exception-safe per rule; actions performed in SQL) and to enqueue webhook deliveries. Event triggers on existing tables (gated by workflow_automation OR integrations; exception-safe): vehicle.created, issue.created, issue.resolved, work_order.completed, inspection.failed, renewal.completed, invoice.issued, payment.received, certificate.issued, customer.created. UI: rules list, rule builder (event picker, condition rows, action rows), run log, "test rule" dry-run RPC against a sample payload.
- **integrations** — API keys UI (create → show once with copy, scopes, expiry, revoke, last used), webhook subscriptions `webhook_subscriptions` (url https-only check, events text[], secret (generated, shown once), active, failure_count), delivery outbox `webhook_deliveries` (subscription, event id, status pending|delivered|failed, attempts, next_attempt_at, response_code, last_error). Worker endpoint `POST /api/integrations/dispatch` (requireAuth; any member of the tenant; delivers that tenant's due pending deliveries with HMAC-SHA256 signature header `X-FleetManage-Signature`, timeout 10s, exponential backoff, max 6 attempts; uses service role scoped by tenant). SPA calls dispatch after the integrations page loads and offers "Deliver now". Public REST API docs page (static, in-app) describing `/api/v1/*` endpoints owned by telematics/logistics (list them from the spec files). Worker file `worker/integrations.ts`.
- **audit_security** — Audit log viewer over `audit_events` (filters: table, action, actor, date range, entity id; diff viewer showing old→new per field; paginated), member access review via worker `GET /api/security/members` (admin: members with role, last_sign_in_at, created_at, email confirmed — from auth admin API) and `POST /api/security/members/:id/sign-out` (admin: `auth.admin.signOut(userId, 'global')` — revokes sessions; refuse self), `security_settings` (tenant-level: session_idle_minutes (enforced client-side by an idle timer when module on), require_strong_passwords bool (informational), audit_retention_days) + a security posture checklist (derived: # admins, members without recent sign-in, api keys without expiry, webhook subscriptions failing). Worker file `worker/security.ts`.
- **multi_company** — Companies & branches CRUD (the foundation tables), assign vehicles/drivers/employees/warehouses to branches (bulk assign screen with multi-select), branch summary cards (counts per branch), default company. A small `useBranchPicker` in pickers (the wiring step adds it). No per-document letterhead switching in v1.
