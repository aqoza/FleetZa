Audit base: `857ce22` (PR #59). Dependency evidence: `shared/modules.ts`
`MODULES[].requires`; the table below is generated by reversing those edges.
Runtime SQL references also exist across modules; their full graph is not claimed
to be captured here. To cover that uncertainty, every external behavior change
runs the complete SQL matrix, unit suite, and build rather than only direct
consumers. UI changes additionally run the relevant browser matrix.

Acceptance commands (repository root, local fixtures; no production credentials):

```powershell
node docs/buildout/pglite/harness.mjs build
node docs/buildout/pglite/verify.mjs
npm test
npm run build
```

Every module uses the complete commands above. The Focus column identifies its
most relevant SQL suite; core modules without a dedicated SQL suite receive
foundation checks, unit tests, route rendering, and live read checks. This is
explicitly not a claim of live UI create/update/delete coverage for every module.
